# Sharding

## Summary

This source explains sharding as splitting one logical dataset across multiple database machines or clusters when a single database can no longer handle capacity, write throughput, read throughput, or operational windows. [[2026-05-15--sharding|Sharding]] It emphasizes that sharding is not a system-design starting point; the designer should first prove that a single database plus indexes, replicas, caching, or other simpler read-path changes is not enough. [[2026-05-15--sharding|Sharding]] The source distinguishes sharding from partitioning and, by implication, from replication: partitioning splits data inside one database instance, sharding splits data across machines, and replication keeps copies of the same data on multiple machines. [[2026-05-15--sharding|Sharding]] Its main practical guidance is to pick shard keys from access patterns and consistency boundaries, then account for hot keys, scatter-gather queries, cross-shard transactions, and resharding. [[2026-05-15--sharding|Sharding]]

## Key Claims

1. Sharding should be introduced only after there is a concrete bottleneck in storage capacity, read throughput, write throughput, or operational manageability. [[2026-05-15--sharding|Sharding]]
2. Partitioning and sharding solve different scopes of problem: partitioning improves management within one database instance, while sharding distributes data and load across database machines. [[2026-05-15--sharding|Sharding]]
3. A good shard key has high cardinality, relatively even distribution, and alignment with common query paths and strong-consistency operations. [[2026-05-15--sharding|Sharding]]
4. The most important sharding design questions are which access pattern dominates, which records must remain in one transaction, whether hot keys exist, and how expensive future resharding will be. [[2026-05-15--sharding|Sharding]]
5. Range-based, hash-based, and directory-based sharding each trade off routing simplicity, range-query support, distribution, operational flexibility, and resharding cost. [[2026-05-15--sharding|Sharding]]
6. Sharding makes some operations more expensive: hot shards, cross-shard queries, cross-shard transactions, routing metadata, and resharding become design concerns. [[2026-05-15--sharding|Sharding]]
7. The strongest system-design answer ties shard key choice to business invariants, such as keeping Airbnb inventory by home and date on one shard or keeping Polymarket matching by market on one ordering boundary. [[2026-05-15--sharding|Sharding]]

## Concepts Mentioned

- [[database-sharding|Database Sharding]] — Splitting one logical dataset across database machines or clusters. [[2026-05-15--sharding|Sharding]]
- [[database-partitioning|Database Partitioning]] — Splitting large tables inside one database instance for management and query efficiency. [[2026-05-15--sharding|Sharding]]
- [[replication|Replication]] — The contrasting pattern that copies the same data across machines rather than partitioning it. [[2026-05-15--sharding|Sharding]]
- [[shard-key|Shard Key]] — The routing key used to decide where a record belongs. [[2026-05-15--sharding|Sharding]]
- [[range-based-sharding|Range-Based Sharding]] — Assigning contiguous key ranges to shards. [[2026-05-15--sharding|Sharding]]
- [[hash-based-sharding|Hash-Based Sharding]] — Hashing keys to spread records across shards. [[2026-05-15--sharding|Sharding]]
- [[virtual-buckets|Virtual Buckets]] — Routing keys through many logical buckets before mapping buckets to physical shards. [[2026-05-15--sharding|Sharding]]
- [[consistent-hashing|Consistent Hashing]] — A hashing strategy that limits key movement when shards are added or removed. [[2026-05-15--sharding|Sharding]]
- [[directory-based-sharding|Directory-Based Sharding]] — Using a routing directory or mapping service to locate each tenant, key, or bucket. [[2026-05-15--sharding|Sharding]]
- [[hot-key|Hot Key]] — A key or object whose traffic can overload its shard even when data volume is evenly distributed. [[2026-05-15--sharding|Sharding]]
- [[scatter-gather-query|Scatter-Gather Query]] — Sending a query to multiple shards and merging partial results. [[2026-05-15--sharding|Sharding]]
- [[cross-shard-transaction|Cross-Shard Transaction]] — A transaction that spans more than one shard and therefore loses the simplicity of a single database transaction. [[2026-05-15--sharding|Sharding]]
- [[single-shard-transaction|Single-Shard Transaction]] — A transaction kept inside one shard by choosing boundaries that match consistency invariants. [[2026-05-15--sharding|Sharding]]
- [[resharding|Resharding]] — Moving data or buckets when the shard layout changes. [[2026-05-15--sharding|Sharding]]
- [[denormalization|Denormalization]] — A way to build read models that avoid frequent cross-shard queries. [[2026-05-15--sharding|Sharding]]
